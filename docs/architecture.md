# Architecture

Parlora Hub is a Laravel application with a React front end, run locally
with Docker Compose for a single learner and built so it can be published
later without a rewrite. This page describes the system as it stands after
Phase 0 (the skeleton) and the boundaries later phases build on. Decisions
with their trade-offs live in [`docs/adr/`](adr/).

## Components

| Component        | Technology                                      | Role                                                                 |
| ---------------- | ----------------------------------------------- | -------------------------------------------------------------------- |
| Web application  | Laravel 13 on PHP 8.5, Fortify, Filament 5      | Routing, authentication, authorisation, grading, the content panel   |
| Front end        | Inertia 3, React 19, TypeScript, Tailwind 4     | Pages rendered in the browser from props sent by Laravel             |
| UI primitives    | shadcn/ui on Radix, themed by the design tokens | Buttons, inputs, dialogs, the sidebar                                |
| Database         | PostgreSQL 17                                   | Accounts, the content model and, from Phase 2, progress and attempts |
| Queues and cache | Valkey 9, Laravel Horizon                       | Background jobs (the `redis` connection), with an admin-only board   |
| Mail             | Mailpit (development)                           | Captures every email sent locally                                    |
| Runtime          | Docker Compose project `parlora-hub`            | The `app` service plus the three services above                      |

The `app` service is built from the project's `Dockerfile` and runs
`composer dev`: `php artisan serve`, Horizon, the log tail and Vite, together
([ADR 0002](adr/0002-php-environment.md)). The same image runs in CI and,
later, on the server. Every port is published on `127.0.0.1` only.

```text
browser ──HTTP──▶ app (Laravel + Inertia) ──▶ postgres
   ▲                     │        └──────────▶ valkey ◀── Horizon workers
   └── Vite (dev, HMR) ◀─┘                     mailpit ◀── outgoing mail
```

### Request flow

A request reaches a Laravel route; middleware authenticates it and
`HandleInertiaRequests` adds the shared props (the signed-in user, feature
flags, the locale and its translations). The route returns an Inertia
response naming a page under `resources/js/pages/`, and React renders it in
the browser. Route helpers for the front end are generated by Wayfinder from
the Laravel routes (`resources/js/routes/`, git-ignored).

Anything that decides access or grades an answer runs on the server. Page
props never carry solutions before the learner answers.

## Accounts and access

- Authentication comes from Fortify (login, password reset, two-factor,
  passkeys). `HUB_REGISTRATION_ENABLED=false` removes the registration
  routes, so the sign-up page returns 404 and its links disappear.
- `users.is_admin` marks administrators. It is never mass-assignable and
  never sent to the browser; it is granted or revoked with
  `php artisan hub:make-admin {email} {--revoke}`. It opens the Horizon
  board (`viewHorizon` gate) and, with a verified email and confirmed
  two-factor authentication, the content panel.
- `users.learner_ref` is an opaque UUID created at sign-up and never changed.
  It is the only identifier Hub will share with Parlora Tutor.

## Content model

The syllabus (CEFR A1–C1) is data. Nine tables hold it; every one has a
stable `key`, an `archived_at` and timestamps.

```text
levels ─┬─< units ─< lessons ─┬─< vocabulary_items
        │                     └─< exercises >─┐
        └─< exams (kind=level)                ├── passages
            exams (kind=placement, no level)  │
              └─< exam_sections ─< exam_questions >─┘
```

- **Hierarchy and order:** each child has an explicit `position`, unique
  within its parent, and relationships return children ordered by it. Foreign
  keys are `ON DELETE RESTRICT`, so a parent with children cannot be deleted.
- **Stable keys:** lowercase dot-separated segments (`a1.u03.l02.ex05`), unique
  per table, at most 120 characters and immutable (a model hook throws
  `LogicException` on change). The importer upserts by key; ids never appear in
  `content/` files.
- **Enums:** `CefrLevel`, `LessonType`, `VocabularyKind`, `Skill`,
  `ExerciseType`, `ExamKind`, `ExamSkill` and `GradingMode` are PHP backed enums
  stored as strings with a database `CHECK`.
- **Translations:** `lessons.theory`, `vocabulary_items.meaning`,
  `exercises.explanation`, `exam_questions.explanation` and rubric descriptions
  are jsonb per locale. English is required, other locales must be listed in
  `hub.content_locales`, and a missing locale falls back to English. Titles,
  prompts and passages stay English.
- **Payloads:** an exercise or exam question stores `content` (what the learner
  sees) and `solution` (server only) as jsonb. `ExercisePayloadCast` reads the
  row's `type` and hydrates the matching `spatie/laravel-data` classes under
  `App\Data\Exercises`, so no PHP class name reaches the database. A `saving`
  hook calls `ExercisePayloads::validate()`, which also checks cross-field
  rules (option ids, gap markers, permutations) and reports `content.*` /
  `solution.*` paths. Exams reuse the same catalogue as lessons.
- **Exams:** a level exam references exactly one level (`CHECK` plus a unique
  `level_id`); the placement exam has no level and only one can be active (a
  partial unique index). Sections carry `grading_mode` (`auto`, `ai`,
  `self_assessment`) and an optional `questions_per_attempt` for the random
  subset drawn from their bank.
- **Passages and audio:** reading and listening material lives in `passages`,
  shared by exercises and exam questions and impossible to delete while used.
  Audio is a relative path on the private `content-audio` disk, validated
  against traversal; nothing is publicly served.
- **Archival:** rows are archived (`archive()`, `restore()`, `active()` scope),
  never deleted and never hidden by a global scope, so attempts and mistakes
  keep resolving them.
- **Solutions never serialise:** `solution` (exercises, exam questions) and
  `transcript` (passages) are in `$hidden`; tests serialise every model, nested,
  and an arch test requires any model with such a column to hide it.

## Content files

The course is authored as JSON files and written to the content tables by
`php artisan content:import`. The files win: the database follows them.

```text
<HUB_CONTENT_PATH>/              default: content/ (relative paths resolve against the project root)
  levels/
    a1/
      level.json                 the level row
      units/
        01-greetings.json        one unit, its lessons, their vocabulary and exercises
        02-family.json
      exam.json                  the A1 level exam, its sections and questions (optional)
  passages/
    a1/reading-01.json           one passage per file, any sub-folders
  exams/
    placement.json               the placement exam (optional)
```

- **Layout.** A level folder is named after its CEFR code in lowercase and its
  `level.json` states the same `code`; levels are ordered by CEFR, units by
  file name (use a zero-padded prefix such as `01-`). The level exam's level
  and the placement exam's kind come from where the file is. Renaming a file
  never renames a row.
- **Row shape.** Every row has a `key`. Parents come from nesting
  (`lessons[] → vocabulary[], exercises[]`, `sections[] → questions[]`) and
  order from array order, so there is no parent key, `position`, id, timestamp
  or `archived_at`. Exercises and exam questions name a passage by key.
  Translations are always `{locale: text}` objects, enums use their stored
  values and payloads are exactly what the model stores. An optional `$schema`
  member points editors at the schema and is ignored.
- **Validation.** `php artisan content:validate` reads only `*.json` under the
  root (no symlinks out of it, at most 1 MiB per file) and reports every
  problem at once as `<file> <pointer>: <message>`. The first layer is JSON
  Schema 2020-12 (`resources/schemas/content/`); the second checks keys
  (format, unique per table across files), passage references, folder and
  code, payloads through `ExercisePayloads::validate()`, translation locales
  and audio path format. Missing audio files and unit files without a numeric
  prefix are warnings. The command needs no database, and CI runs it whenever
  the repository has a `content/` folder.
- **Import.** `content:import` validates first and writes nothing on an error.
  Then it plans per table what to create, update, leave unchanged, archive and
  restore, and writes it in one transaction under an advisory lock, parents
  before children, through Eloquent so the model hooks still guard every row.
  A row that moved to another parent keeps its id; positions are rewritten in
  three steps so `unique(parent, position)` never breaks. An unchanged row is
  not written, so re-importing the same tree changes nothing. Panel edits to a
  row that is still in the files are overwritten.
- **Archival on absence.** A row whose key appears in no file is archived,
  never deleted, and moves after its active siblings; an archived row whose
  key returns is restored and updated. Archivals happen before creations, so
  a new placement exam can replace the old one.
- **Dry run and summary.** `--dry-run` prints the same per-table summary
  (created, updated, unchanged, archived, restored) and rolls back. Audio paths
  missing from the `content-audio` disk are warnings and never fail an import.
- **Location.** `HUB_CONTENT_PATH` sets the root (`hub.content_path`) and
  `--path` overrides it for one run of either command.

### A1 course

`content/levels/a1/` holds the A1 course: an original syllabus written from
the public CEFR A1 descriptors, in eight themed units (`01-hello.json` …
`08-now-and-then.json`) and the A1 exam.

- **Unit template.** Four lessons in a fixed order: grammar, vocabulary, then
  reading and speaking in odd units or listening and writing in even ones. The
  last lesson reviews the unit before its production task. Keys follow
  `a1.u01`, `a1.u01.l01`, `a1.u01.l01.ex01` and `a1.u01.l02.v01`.
- **Minimums.** Every lesson has theory and at least 10 exercises of at least
  4 types, from recognition to free production; a vocabulary lesson has at
  least 12 items. Writing and speaking tasks (at most two, with a rubric) only
  appear in the last lesson, dictations only in listening lessons, and every
  auto-graded exercise has an explanation.
- **Languages.** Theory, meanings, explanations and rubric descriptions carry
  English and Spanish; titles, prompts, examples and passages are American
  English.
- **Audio later.** Listening passages and dictations carry an `audio_path`
  under `a1/`; the files are produced separately, and until then the import
  lists them as warnings.

`tests/Feature/Content/A1CourseTest.php` checks these rules over the shipped
tree (failures name the file, pointer or key), and `A1ImportTest` imports it
into an empty database.

## Content panel

A Filament 5 panel at `/admin` lets an administrator touch up the content
tables. JSON under `content/` stays the source of truth: the panel retouches
rows and never authors new ones.

- **Access.** The `accessContentPanel` gate (in `AdminPanelServiceProvider`)
  requires `is_admin`, a verified email and confirmed two-factor
  authentication. `User::canAccessPanel()` delegates to it, so the rule lives
  in one place and is checked on every request, Livewire updates included. A
  user who fails it gets a 403, not a redirect. The panel shows solutions and
  transcripts, so this gate is the security boundary.
- **Hub's login.** The panel has no login page of its own. A guest is sent to
  Fortify's `/login` and returns to `/admin` afterwards; a passkey sign-in
  counts the same as a password plus TOTP.
- **Touch-ups only.** There are no create, delete or replicate actions in the
  UI, and the content policies (one abstract `ContentPolicy`, nine thin
  subclasses) deny them too. Filament's strict authorization is on, so a
  missing policy method throws. Editing, reordering, moving a row to another
  parent, archiving and restoring are allowed; `key` is read-only.
- **Navigation.** Levels, Passages and Exams. Units, lessons, vocabulary,
  exercises, exam sections and questions are reached by drilling down through
  relation managers.
- **Validation.** Payload editors (`content`, `solution`) go through
  `ExercisePayloads::validate()` and report errors on the field with their
  path; translations are one field per locale in `hub.content_locales`, with
  English required when the attribute is.
- **Re-import notice and Copy as JSON.** Every edit page warns that the next
  `content:import` overwrites panel edits. _Copy as JSON_ exports the row as a
  content-file fragment (passage by key, active children nested in order, no
  ids, parent keys, positions or timestamps) that pastes straight into
  `content/`.
- **Look.** Brand accent `#3550E6` and Figtree served from `public/fonts/`;
  no font comes from a third-party host.

The test suite runs on PostgreSQL, never SQLite: `phpunit.xml` selects the
`hub_test` database and a guard in `tests/TestCase.php` refuses any other
connection or a database name that does not end in `_test`.

## Parlora Tutor boundary

[Parlora Tutor](https://github.com/Mvh18/parlora-tutor) is a separate
product: the voice-AI engine for calls and AI grading of speaking and
writing. Hub is the learner-facing product and uses Tutor **only through its
HTTP API**. It never imports Tutor code or reads Tutor's database.

- **Data ownership:** Hub owns identity, progress, attempts, the mistakes
  notebook and spaced repetition (FSRS). Tutor owns conversations, keyed by
  `learner_ref`.
- **Contract:** Tutor's `contracts/openapi.json` is the source of truth; Hub
  keeps a versioned copy for CI from Phase 6. The planned flows are in
  [INTEGRATION.md](INTEGRATION.md).
- **Configuration:** `config/parlora_tutor.php` reads `PARLORA_TUTOR_ENABLED`
  (default `false`), `PARLORA_TUTOR_URL`, `PARLORA_TUTOR_API_KEY` and
  `PARLORA_TUTOR_WEBHOOK_SECRET`. Nothing reads it yet: Phase 6 adds the
  `ParloraTutorClient` HTTP client and the signed webhooks.
- **Network:** the two Compose projects will share the external Docker
  network **`parlora-net`**, so Hub reaches Tutor by service name. The name
  is reserved; neither project declares the network until Phase 6.
- **Optional by design:** with the integration off, or with Tutor down, Hub
  keeps working; only calls and AI grading are disabled, with a clear
  notice. The test suite runs with `Http::preventStrayRequests()`, so any
  unplanned outbound request fails it.

## Design system

The brand's look is defined once, as **design tokens** in
`resources/css/tokens.css`: colours for the light and the dark theme,
radii (including the speech-bubble corners), shadows and the type scale.
`resources/css/app.css` maps them into Tailwind's `@theme` and the shadcn/ui
variables, so components use utilities such as `bg-surface`,
`text-ink-muted` or `bubble-bl` and never raw colour values.

- The tokens are the design source. The original mockups are reference
  material outside the repository, not something to copy styles from.
- Tests check every declared text/background pair against WCAG 2.2 AA in
  both themes, and reject hex values, colour functions and Tailwind palette
  colours in `resources/js`.
- Bricolage Grotesque (headings) and Figtree (UI and body) are self-hosted
  from Fontsource packages; no request goes to a third-party font host.
- Interactive targets are at least 44 px, primary buttons 48 px.

## Interface language

The interface is English-only, and every user-facing string lives in
`lang/en/*.php`, one file per area (`auth`, `nav`, `home`, `settings`, …).
`HandleInertiaRequests` shares the active locale's groups with React (all but
the server-only `pagination`, `passwords` and `validation`), resolved once
per locale. Components read them through `useTrans()`:

```tsx
const { t } = useTrans();
t('home.greeting.afternoon', { name: 'Alex' }); // "Good afternoon, Alex"
```

The helper supports Laravel's `:placeholder` and plural syntax and throws on
a missing key in development and tests. Oxlint's `react/jsx-no-literals`
rejects hard-coded text in JSX, and a Pest test checks that every key the
front end uses exists.

## Quality gates

| Check      | Command (inside the `app` service) | Covers                                                                               |
| ---------- | ---------------------------------- | ------------------------------------------------------------------------------------ |
| PHP        | `composer check`                   | Pint, Larastan (level 8), Pest with coverage ≥ 85 % and ≥ 95 % on gates and policies |
| JavaScript | `pnpm check`                       | Oxfmt, Oxlint, `tsc --noEmit`, Vitest                                                |
| Build      | `pnpm build && pnpm check:build`   | Production assets, fonts served locally                                              |

CI runs the same checks plus a Compose smoke test, dependency audits and
licence policy; a single required status, `ci-ok`, aggregates them.
